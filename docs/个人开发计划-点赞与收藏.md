状态：已开始开发本人点赞与收藏模块，先完成点赞与取消点赞；另一位成员的分工仍需组内确认。

## 现状与选题依据

- 已有注册登录、发布、搜索、配图、内容审核和用户封禁功能。
- `likes`、`collections` 数据表及 ORM 模型已经存在，数据库已有用户与微澜组合的唯一约束。
- 首页卡片和详情页目前只显示点赞数量，没有点赞或收藏操作入口。
- 后端没有点赞、取消点赞、收藏、取消收藏和我的收藏列表接口。
- 回声已有模型、读取和树形展示代码，但没有发表、回复接口与表单，适合交给另一位成员独立开发。
- 本地当前历史只有两个提交，后续按真实完成的阶段持续提交，保留开发过程。

## 本人模块的验收标准

1. 登录用户可对公开微澜点赞、取消点赞，数量和按钮状态正确更新。
2. 连续点击或重复请求不会产生重复记录；取消操作可安全重复。
3. 登录用户可收藏、取消收藏；刷新页面和重新登录后仍能正确读取状态。
4. 个人中心可分页查看自己的收藏、进入详情、取消收藏。
5. 不同账号的点赞和收藏状态独立，不能操作其他人的收藏记录。
6. 未登录用户不能执行互动操作；封禁用户按现有认证规则拒绝操作。
7. 封禁、待审核或已删除的微澜不通过收藏列表暴露给其他用户，也不能继续被互动。
8. 首页、详情页和收藏页重新加载后得到一致的状态；请求失败时给出提示，避免按钮卡住。

## 建议接口

以下为设计草案，实施时与另一位成员确认后定稿。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| PUT | `/api/v1/interactions/ripples/{id}/like` | 设置已点赞，重复调用保持已点赞 |
| DELETE | `/api/v1/interactions/ripples/{id}/like` | 取消点赞，重复调用保持未点赞 |
| PUT | `/api/v1/interactions/ripples/{id}/collection` | 设置已收藏 |
| DELETE | `/api/v1/interactions/ripples/{id}/collection` | 取消收藏 |
| GET | `/api/v1/interactions/collections` | 当前用户的收藏列表，支持 limit、offset |

微澜响应增加当前用户的 `is_liked`、`is_collected` 字段；匿名请求返回 false。现有 `like_count` 字段继续使用。批量查询当前用户状态，避免为每张卡片单独发送请求。
